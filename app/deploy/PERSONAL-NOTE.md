# ⚠ 个人版（Personal Edition）—— 占位说明

> **状态**：★ **尚未立项** —— 本文只记录已确认的约束，避免将来搭错。
> **相关**：`docs/PRODUCT-VERSIONS.md`（三版定位）· `docs/JOB-MODEL.md` J10.3（Parser 接口）

---

## 一、⚠ 为什么它**不在这套 Docker 里**

| | 公开版 / 企业版 | ★ 个人版 |
|---|---|---|
| 部署位置 | 服务器 | ★ **用户本机** |
| 技术栈 | Python + Django | ⚠ **Node.js**（用户设想） |
| 数据库 | PostgreSQL | ★ **SQLite** |
| 用户模型 | 多用户 | ★ **单用户** |
| 网络 | 联网 | ★ **可完全离线** |
| 交付物 | Docker 镜像 | ⚠ **单文件可执行程序**（用户本机不一定装 Docker） |

⇒ ⚠ **它是【独立技术栈】，不能与公开版共用同一个 Dockerfile。**
⇒ ★ 因此 `Dockerfile` 里**没有** `personal` 目标 —— 那是**故意的**，不是遗漏。

---

## 二、已确定的约束（来自 `PRODUCT-VERSIONS.md`）

| # | 约束 |
|---|---|
| **1** ★★ | **本地解析** —— 必须能解析用户自己的代码（含**公司私有代码**）；否则「带图的笔记」**没有图的来源** |
| **2** ★ | **单用户 + SQLite** |
| **3** ★★ | **私有源码永不上行**（`H1`）—— 数据只在本机 |
| **4** ★ | **支持导入 `.webapkg`**：新建项目 → 灌数据 → ★ **得到与导出方一模一样的图与解释**（`B119`） |
| **5** ★★ | **能和公开版交换数据** —— `.webapkg` 是三版通用的"货币"（`WEBAPKG-SPEC.md`） |

---

## 三、★ 与公开版应该共享什么（**建议，待立项时定**）

```
★ 建议共享（同源、保证格式一致）
   · 解析器的【Parser 接口与产出结构】（JOB-MODEL.md J10.3）
   · .webapkg 格式与字段 Schema（WEBAPKG-SPEC / GRAPH-SCHEMA）
   · 图 / 锚点 / 笔记的语义定义

⚠ 不建议共享
   · Web 框架与 ORM（Django vs Node 生态不同）
   · 部署方式（服务端 vs 本机）
```

⇒ ★ 原则：**共享"标准"，不共享"实现"** —— 这与 `S2.1` 把格式定位为「标准」一致。
