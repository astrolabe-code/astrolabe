# 图数据 Schema

> **本文的地位**：`.webapkg` **内容字段**的现行依据（包结构见 `WEBAPKG-SPEC.md`，两者配套）。
> **写作时间**：2026-09-19（开工前，尚无代码）
> ⚠ **本文所有字段决策，都必须服从 S0 的三条铁律。**
> ⚠ **2026-09-19 修订**：引用键由 `uid` 改为 **`pkg_id`** —— 见 **S7**（原因：`uid` 允许重复，**不能用来挂载解释**）。

---

## S0 ★★★ 三条铁律（**用户强调，最高优先级**）

> **① 让我网站的导出数据有成为「行业标准」的潜力。**
> **② 方便 AI 读取** —— 以后会大面积用 AI；★ 这也是**潜在的与 gitnexus 竞争**（他也有一套标准）。
> **③ 方便人们下载与重建。**

| # | 铁律 | 对字段设计的约束 |
|---|---|---|
| **1** | ★ **标准潜力** | **自足**（不依赖私有实现）· **核心极小且稳定** · **扩展位明确** |
| **2** | ★★ **AI 友好** | **自描述** · **扁平** · **英文直白命名** · **文件即接口**（不装工具也能读） |
| **3** | ★★★ **可下载可重建** | ★★ **引用一律用 `pkg_id`**（**因为 `uid` 可能重复**，见 S7）· ★ **解释保证不会挂错** · 不依赖服务器 · 不含状态 |

> ⚠ **任何字段的取舍，都拿这三条来判** —— 违反其中任意一条，宁可不加这个字段。

## S1 设计总则

| 原则 | 说明 |
|---|---|
| ★ **JSONL**（一行一对象） | 流式读写 |
| ★★ **字段名英文、语义直白** | ✅ `file_path`　❌ `fp`；✅ `kind`　❌ `t` |
| ★★★ **引用用「包内序号」`pkg_id`** | ⚠ **不用 `uid` 做引用** —— `uid` 允许重复（`B117`），**拿它挂载解释会挂错**；序号是**发号的，保证唯一**（详见 S7） |
| ★★ **可读冗余** | 引用处**附带** `*_uid` 字符串，供人 / AI 直接读，**但不得作为挂载依据** |
| ★ **人类可读信息与机器信息并存** | 同时给 `uid` 和 `name` / `signature` —— ★ **AI 也需要"这是干什么的"** |
| ★★ **可选字段一律可省略** | 缺字段 ≠ 报错；接收方按默认值处理 |
| ★ **每类对象保留 `extra`** | ★ **扩展位** —— 塞不进标准字段的语言特有信息放这里 |

## S2 节点（`graph/nodes.jsonl`）

```json
{
  "pkg_id": 1,
  "uid": "function#src/main.c#main",
  "kind": "function",
  "name": "main",
  "qname": "",
  "file_path": "src/main.c",
  "line": 12,
  "line_end": 28,
  "lang": "c",
  "signature": "int main(int argc, char **argv)",
  "doc": "程序入口",
  "extra": {}
}
```

| 字段 | 必选 | 说明 |
|---|---|---|
| ★★ **`pkg_id`** | ★ **必选** | ★ **包内唯一序号**（1..N，由导出方发号）—— ★ **包内所有引用的依据** |
| **`uid`** | ★ **必选** | ★ **人类可读标签**（`<kind>#<path>#<name>#<重载键>`）—— ⚠ **可能重复，❌ 不用于引用** |
| **`kind`** | ★ **必选** | `file` / `dir` / `function` / `method` / `type` / `macro` / `variable` / `constant` / `field` … |
| **`name`** | ★ **必选** | 显示名（人有；★ AI 也需要） |
| `qname` | ○ | 限定名（C++ / Java 的 `ns::Class::method`） |
| **`file_path`** | ★ **必选** | 相对路径（`/` 分隔） |
| **`line`** | ★ **必选** | 起始行（1-based）—— ★ 锚点的落点 |
| `line_end` | ○ | 结束行 |
| **`lang`** | ★ **必选** | `c` / `cpp` / `python` / `java` / `asm` |
| `signature` | ○ | ★ **签名原文**（人能读、便于 AI 理解；重载靠它区分） |
| `doc` | ○ | 注释 / 文档串 |
| ★ `extra` | ○ | ★ **扩展位**（语言特有） |

> ⚠ **不导出 `vid`**（服务器发号的内部标识）—— 它在别的实例上**没有意义**。
> ○ 若需保留来源实例信息，放 `extra.source_vid`。

## S3 边（`graph/edges.jsonl`）

```json
{
  "from": 1,
  "to": 87,
  "from_uid": "function#src/main.c#main",
  "to_uid": "function#src/util.c#helper",
  "type": "calls",
  "origin": "parsed",
  "line": 15,
  "confidence": "syntax",
  "extra": {}
}
```

| 字段 | 必选 | 说明 |
|---|---|---|
| ★★ **`from`** / **`to`** | ★ **必选** | ★ **`pkg_id`（数字）** —— **引用依据** |
| ★ `from_uid` / `to_uid` | ○ | ★ **可读冗余**（供人 / AI 直接看）—— ⚠ **不得作为挂载依据** |
| **`type`** | ★ **必选** | `calls` / `imports` / `includes` / `defines` / `contains` / `overrides` / `implements` … |
| **`origin`** | ★ **必选** | `parsed` / `manual`（★ 与 `GRAPH-STORAGE.md` G1 一致） |
| `line` | ○ | 该关系**发生的位置**（如调用点） |
| `confidence` | ○ | `syntax` / `semantic` —— ★ 语法级拿不到精确调用图时**如实标注** |
| ★ `extra` | ○ | 扩展位 |

## S4 锚点（`anchors.jsonl`）

★ **锚点是本平台的核心价值** —— 它是"解释"与"代码位置"的连接点。

```json
{
  "anchor_id": "a_0001",
  "target_pkg_id": 1,
  "target_uid": "function#src/main.c#main",
  "kind": "symbol",
  "file_path": "src/main.c",
  "line_start": 12,
  "line_end": 28
}
```

| 字段 | 必选 | 说明 |
|---|---|---|
| `anchor_id` | ★ **必选** | 包内唯一（★ 笔记通过它挂载） |
| ★★ **`target_pkg_id`** | ★ **必选** | ★ **挂在哪个节点（`pkg_id`）** —— **唯一的挂载依据** |
| `target_uid` | ○ | ★ 可读冗余 —— ⚠ **不得作为挂载依据** |
| **`kind`** | ★ **必选** | `symbol`（挂节点）/ `line_range`（挂行区间）/ `file` |
| **`file_path`** | ★ **必选** | ★ 结构坐标（便于人核对、便于诊断） |
| `line_start` / `line_end` | ○ | `line_range` 类锚必填 |

## S5 解释 / 笔记（`annotations/notes.jsonl`）

```json
{
  "anchor_id": "a_0001",
  "kind": "explanation",
  "author": { "name": "mahvm", "account": "mahvm", "url": "https://github.com/mahvm" },
  "created_at": "2026-09-19T09:00:00Z",
  "updated_at": null,
  "title": "这里容易看错",
  "body_md": "这个函数第 12–28 行……",
  "extra": {}
}
```

| 字段 | 必选 | 说明 |
|---|---|---|
| **`anchor_id`** | ★ **必选** | 指向 S4 的锚点（★ 锚点再指向 `pkg_id`） |
| **`kind`** | ★ **必选** | `explanation` / `question` / `answer` / `path_step` |
| ★★ **`author`** | ★ **必选** | ★ **署名不可缺**（`S2.5`：署名跟着数据走） |
| **`body_md`** | ★ **必选** | ★ Markdown 正文（★ AI 与人都能读） |
| `created_at` / `updated_at` | ○ | 时间戳 |
| `title` | ○ | 标题 |

> ⚠ **强制**：含此文件 ⇒ **必须保留每条笔记的 `author`**（任何工具重新打包**不得抹除署名**）。

## S7 ★★★ 引用规则与「解释不会挂错」（**本文的成败所在**）

### S7.0 ⚠ 先说清修正前的漏洞（2026-09-19）

```
修正前的设计（已作废）：
   包内引用用 `uid` —— 理由：人类可读、跨机器一致

⚠ 致命漏洞：
   `B117` 已明确【uid 允许偶发重复】（为了可读性）
   ⇒ ★ 拿一个"允许重复的东西"当挂载标准 ⇒ ★ 解释可能挂错！

★ 用户裁定：
   「新机器上挂载解释不要以 uid 为标准，它可能重复的。
     设计重点应该是【解释保证不会挂错】。」
```

### S7.1 ★★★ 定案：**包内引用一律用 `pkg_id`**

```
★ 每个节点在包内有一个 `pkg_id`（1..N，导出方发号，★ 包内【保证唯一】）
★ 包内所有引用一律用 `pkg_id`：
     边的 from / to          → pkg_id（数字）
     锚点的 target            → target_pkg_id
     笔记的引用               → anchor_id（锚点再指向 target_pkg_id）
     集合 / 流程的成员          → pkg_id

★ `uid` 降级为【人类可读标签】：
     ✅ 展示、搜索、给人看
     ✅ 跨版本匹配的辅助线索
     ❌ 不再作为【任何】挂载依据
```

### S7.2 ★★ 为什么这样就"不会挂错"

| 环节 | 依据 | 是否可能出错 |
|---|---|---|
| **包内引用** | `pkg_id`（包内发号，保证唯一） | ★ **不可能** ✅ |
| **导入映射** | `pkg_id` → 本机新 `vid`（一对一） | ★ **不可能** ✅ |
| **解释挂载** | 只走 `pkg_id → vid` 一条路 | ★ **绝不使用 `uid`** ✅ |

> ★★ **一句话**：**`pkg_id` 保证「包内不错」，`vid` 保证「本机不错」--
> 中间用一次一对一映射连起来。**

### S7.3 ★★★ 三种标识的分工（**本节的核心认知**）

| 标识 | 作用 | 唯一性 | 允许重复？ |
|---|---|---|---|
| **`pkg_id`** | ★ **包内引用** | ★ **包内一定唯一** | ❌ **不允许** |
| **`vid`** | ★ **本机引用 + 锚点挂载** | ★ **本机一定唯一** | ❌ **不允许** |
| **`uid`** | ★ **人类可读标签** | ⚠ 可能重复 | ✅ **允许** |

⇒ ★★★ **规律**：

> **「能重复的」只用来看；「不能重复的」才用来挂。**

### S7.4 ★★ 导入的主场景 = **新建项目**（一期**唯一**要支持的）

**用户澄清（2026-09-19）**：

> 我这导入的意思，更多是**别人拿到导出物，新建一个项目文件，把数据导入进去**，
> **获得一个跟别人一模一样的图与解释**。两台机器上 vid 重不重复，其实**不太重要**。

```
★ 主场景：  别人拿到 .webapkg  →  ★【新建一个项目】→ 灌入数据
            目标 = ★ 得到【与导出方一模一样的图与解释】

★ 流程：
   ① 读 manifest.json → 确认格式版本与能力
   ② 按 pkg_id 写入节点 → ★【本机发号】得到本项目的新 vid
   ③ 建立映射：  pkg_id  →  本机新 vid      （★ 一对一，绝不使用 uid）
   ④ 锚点：target_pkg_id  →（经映射）→  本机新 vid
   ⑤ 笔记：anchor_id  →  锚点  →  本机新 vid
   ⑥ ⚠ 异常（包不完整 / 版本不匹配）⇒ ★ 标记「未定位」，❌ 不丢弃、不静默删
```

⇒ ★ **为什么"vid 不同"仍然"一模一样"**：

| 项 | 由什么决定 | 结论 |
|---|---|---|
| 图的**内容与结构** | 字段 + `pkg_id` 构成的**引用关系** | ★ 相同 ✅ |
| 解释的**归属** | `pkg_id` 链（note → anchor → node） | ★ 相同 ✅ |
| `vid` | ★ **本机行号** —— 只是"本机的引用手段" | △ 不同也无所谓 ✅ |
| `uid` | 人类可读标签 | △ 重复也无所谓 ✅ |

> ★★ **一句话**：**`vid` 是本机的行号，`uid` 是给人看的名字，
> 而「谁连着谁」由 `pkg_id` 唯一决定。**

### S7.5 ⚠「合并 / 去重」= **将来场景**（一期**不做**，只留接口）

**用户裁定**：

> 你的设计是为了**合并两份对同样代码的解释**而设计的，**可考虑**，
> 但**初期应该没人这么做** —— **重复代码，在网站新开一个项目就解决了**。

| 场景 | 一期 | 将来 |
|---|---|---|
| ★ **导入 = 新建项目** | ✅ **唯一支持**（本地本无旧节点 ⇒ **无需去重**） | 保持 |
| ⚠ **合并进已有项目** | ❌ **不做** —— 冲突策略留到真有场景再定 | ○ 保留接口 |
| ⚠ **在已有项目里重复导入** | ★ **必须先提示**（覆盖 / 追加 / 取消），❌ **不得静默合并** | 保持 |

### S7.6 ★ 失败时不丢数据

```
★ 异常（对应节点找不到 / 版本不匹配）⇒ 标记「未定位」，❌ 不丢弃、不静默删
```

★ 理由：**宁可显示"未定位"，也不要悄悄丢掉别人辛苦写的笔记。**

## S8 ★★ AI 读取友好性（7 条具体规则）

> 铁律 ② 的落地。★ 目标是：**任何 AI，不需要装任何工具，直接读文件就能理解。**

| # | 规则 | 为什么 |
|---|---|---|
| **1** ★★ | **JSONL，一行一对象** | ★ 可流式读，不必一次载入 |
| **2** ★★ | **引用用 `pkg_id`，同时带 `*_uid` 可读冗余** | ★ **既不会错、又能直接读懂** —— 不必先跨文件查（代价：略冗余，⚠ 但**冗余不得作为挂载依据**） |
| **3** ★★★ | **人类可读信息与机器信息并存** | 给 `uid` **也**给 `name` / `signature` —— ★ AI 需要知道"这是干什么的" |
| **4** ★ | **英文 + 直白命名，不用缩写** | ✅ `file_path`　❌ `fp` |
| **5** ★ | **扁平优先，避免深嵌套** | 少一层嵌套 = 少一次误解 |
| **6** ★★ | **提供 JSON Schema 文件** | 让 AI/工具能**校验**自己理解得对不对（→ 也是"标准"的一部分） |
| **7** ★★★ | **文件即接口** | ⚠ 不装工具、不连服务器，**打开文件就能用** |

## S9 ★ 与 gitnexus 的差异（**为什么别人会选这个格式**）

| | gitnexus | ★ Astrolabe |
|---|---|---|
| 图的读者 | ★ **AI**（`impact` / `query` / `context`） | ★ **人 + AI** |
| 图的角色 | **索引**（可重建，`analyze` 一下就有） | ★ **坐标系**（锚定 + **不可变**） |
| 数据里有人吗 | ❌ 只有结构 | ★★ **有** —— **解释 / 笔记 / 阅读路径**（人类知识） |
| 署名 | — | ★★ **`authors` 跟着数据走** |
| 打开方式 | 需要它的工具 / MCP server | ★★ **打开文件就能读**（`jsonl`） |

⇒ ★★ **差异化的一句话**：

> **gitnexus 导出的是「代码的结构」，Astrolabe 导出的是「代码的结构 + 人对它的理解」。**

★ 而"**理解**"这部分，**正是 AI 时代最稀缺、也最值钱的数据** —— ⚠ 也是**别的工具抄不走的**。

## S10 版本与扩展

| | 规定 |
|---|---|
| **格式版本** | 见 `WEBAPKG-SPEC.md` W8（major/minor/patch + `capabilities`） |
