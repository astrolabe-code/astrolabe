# `.webapkg` 开放格式规范

> **本文的地位**：数据交换格式的**现行依据**。★ **这是一份「标准」文档，不是「产品」文档** ——
> 目标是**被别人照着实现**（`S2.1` 第 4 项：「`.webapkg` 开放格式 + 开放 API 契约」）。
> **写作时间**：2026-09-19（开工前，尚无代码）
> **来源**：2026-09-19 与用户的设计讨论

---

## W0 目标（用户原话）

> **解析产出的数据一定要方便互相传播**，这给个人版的交流带来了方便 ——
> 一个人可以**下载数据（代码 + 图数据 + 解释笔记），打包发给别人**，然后别人能**很方便地在个人版上重建**。
> 当然可以**选择要导出什么** —— 毕竟有人不喜欢把自己辛苦写的笔记随便给别人看。
>
> **还要注意与 AI 看**，就像 gitnexus 一样 —— 现在与 AI 交互已经不可避免了。
>
> 你可以设计一个**产物格式规则**，就像**微软的语言服务器交互标准**一样。
> **形成标准，别人更知道是谁写的**，就像微软统一了行业标准。

⇒ 五条硬需求：

| # | 需求 |
|---|---|
| **1** | ★ **可打包传播**：代码 + 图 + 解释笔记 → 一个文件 → 对方能**重建** |
| **2** | ★★ **选择性导出**（笔记默认可以不带走） |
| **3** | ★★ **面向 AI**（像 gitnexus 那样提供机器可读的访问层） |
| **4** | ★★★ **成为「标准」**（别人愿意照着实现） |
| **5** | ★★★ **署名**跟着数据走（"别人更知道是谁写的"） |

## W1 ★ 对标 LSP：一个格式要成为标准，需要五个条件

| # | LSP 为什么成了标准 | `.webapkg` 对应做法 |
|---|---|---|
| **1** | ★ **协议与实现分离** | 本文是**独立的规范**；参考实现可以换语言、换作者 |
| **2** | ★★ **能力协商**（capability negotiation） | `manifest.json` 里**声明**本包包含什么、生成器支持什么 |
| **3** | ★★ **最小核心 + 可选扩展** | ★ **核心字段必须支持**；扩展字段**允许忽略**（不实现不报错） |
| **4** | ★★★ **参考实现开源** | 解析器 + 读图器开源（`S2.1`） |
| **5** | ★★★ **多实现可验证** | ★ **你自写的汇编解析器就是「第二个实现」** —— 它能插进来，就证明规范可独立实现 |

> ★ **关键取舍**：标准的力量来自「**别人能不用问你就能实现**」。
> ⇒ 规范必须**自足**（不依赖某个私有实现），且**留好扩展位**。

## W2 包结构

`.webapkg` **本质是 ZIP**（后缀不同，便于识别），内部目录固定：

```
example.webapkg
├── manifest.json              ★ 必选 —— 元数据 / 内容清单 / 署名 / 许可
├── graph/
│   ├── nodes.jsonl            ★ 节点（一行一条 JSON，流式友好）
│   └── edges.jsonl            ★ 边
├── analysis/
│   └── codeanalysis.json      ○ 可选 —— 入口点 / 执行流 / 聚类
├── anchors.jsonl              ★ 锚点（解释与代码位置的连接）
├── annotations/
│   ├── notes.jsonl            ○ 可选 —— 解释 / 笔记（★ 默认不导出）
│   └── paths.jsonl            ○ 可选 —— 阅读路径
└── source/                    ○ 可选 —— 源码（⚠ 含此目录则 manifest 必须带许可声明）
    └── <原目录结构>
```

**格式约定**：

| 约定 | 说明 |
|---|---|
| ★ **JSONL**（一行一 JSON） | 便于**流式读写**，不必一次载入内存；▲ 大包友好 |
| **UTF-8 无 BOM** | —— |
| **路径用 `/` 分隔** | 与语言/平台无关 |
| ⚠ **不打包 `.git` / `node_modules` / 构建产物** | 见排除清单（`backend-parse-flow-current.md` §3.2） |

## W3 `manifest.json` 规范

★ **这是标准的核心** —— 所有实现都要读它。

```json
{
  "format": "webapkg",
  "format_version": "1.0.0",

  "generator": {
    "name": "astrolabe",
    "version": "0.1.0",
    "homepage": "https://github.com/astrolabe-code/astrolabe"
  },
  "created_at": "2026-09-19T09:00:00Z",

  "source": {
    "repo": "https://github.com/torvalds/linux",
    "commit": "abc123...",
    "languages": ["c", "asm"],
    "entries": 1234
  },

  "contents": {
    "graph": true,
    "analysis": true,
    "anchors": true,
    "annotations": false,
    "source": false
  },

  "counts": { "nodes": 9270, "edges": 16041, "anchors": 320, "notes": 0 },

  "authors": [
    { "name": "mahvm", "account": "mahvm", "url": "https://github.com/mahvm" }
  ],
  "license": {
    "kind": "referenced",
    "note": "源码版权归原作者；本包由 Astrolabe 生成，遵循其开放格式规范"
  },

  "capabilities": ["graph", "analysis", "anchors", "annotations"],
  "extensions": {}
}
```

**必选字段**：`format` · `format_version` · `generator` · `created_at` · `source` · `contents` · `counts` · `authors` · `capabilities`

⚠ **`extensions`**：★ **扩展位** —— 任何实现可以往这里塞自己的数据，**别人忽略即可**（W1 条件 3）。

## W4 各部分格式（概要）

> ⚠ **字段级 schema（节点 / 边有哪些列）见 `GRAPH-SCHEMA.md`** —— 本文只规定「**怎么装**」。

| 文件 | 内容 | 说明 |
|---|---|---|
| `graph/nodes.jsonl` | 每个节点一行 | ★ 必含**服务器发号的稳定标识**（见 `GRAPH-STORAGE.md` G3.5） |
| `graph/edges.jsonl` | 每条边一行 | `from` / `to` / `type` / `origin` |
| `analysis/codeanalysis.json` | 入口点 / 执行流 / 聚类 | 可重建（`S2.1` 定位为"标准"的一部分） |
| `anchors.jsonl` | ★ 锚点 | ★ **连接「解释」与「代码位置」的坐标系** —— 本平台的核心价值 |
| `annotations/notes.jsonl` | 解释 / 笔记 | ★ 带作者署名与时间 |
| `annotations/paths.jsonl` | 阅读路径 | 有序的节点引用 |

## W5 ★ 选择性导出

**用户要求**：*"可以选择要导出什么，毕竟有人不喜欢把自己辛苦写的笔记随便给别人看。"*

**规则**：

| 内容 | 默认 | 说明 |
|---|---|---|
| `graph` | ✅ **导出** | 图数据 |
| `analysis` | ✅ **导出** | 分析结果 |
| `anchors` | ✅ **导出** | 锚点（解释的落点） |
| **`annotations`** | ⚠ **不导出** | ★ **包含个人笔记 —— 必须显式勾选** |
| **`source`** | ⚠ **不导出** | ★ **涉及版权 —— 必须显式勾选 + 许可声明** |

⚠ **一致性要求**：`manifest.contents` 里声明为 `true` 的**必须有对应文件**；声明为 `false` 的**不得出现** ——
★ 这样接收方**能先读 manifest 再决定要不要下载其余部分**（大包友好）。

## W6 ★★ 署名与版权

★ 这是"**别人更知道是谁写的**"的技术落点。

| 字段 | 作用 |
|---|---|
| `authors[]` | ★ **数据是谁整理的**（笔记作者 / 包生成者） |
| `source.repo` + `source.commit` | ★ **代码出处**（可回溯 + 时间戳） |
| `license` | ★ 版权归属说明 |
| `generator` | ★ **是哪个工具产出的** —— ★ 让规范本身获得署名 |

⚠ **强制要求**：

```
① 含 source/ ⇒ ★ 必须填 license（禁止出现"无许可的源码包"）
② 含 annotations/ ⇒ ★ 必须保留每条笔记的 author（不得抹除署名）
③ 任何工具重新打包 ⇒ ⚠ 必须保留原 generator 链路（可追溯）
```

> ★ 这与 `S2.5`「**署名保护工具箱**」一致：**署名要跟着数据走**，而不是只挂在网页上。

## W7 ★★ 面向 AI（像 gitnexus 那样）

**用户要求**：*"还要注意与 AI 看，就像 gitnexus 一样，毕竟现在与 AI 交互已经不可避免了。"*

**三层分工**（★ 三者**共用同一套语义接口**）：

```
① 数据层   `.webapkg`（本文）        —— 离线、可传播、可归档
② 文件层   graph/*.jsonl             —— ★ 机器可直接读（无需任何工具）
③ 访问层   MCP Server（可选）        —— AI 通过 MCP 查询（query / context / impact）
```

★ **关键设计**：

| 原则 | 说明 |
|---|---|
| ★ **文件即接口** | ⚠ **不需要装任何工具就能读** —— `jsonl` + `manifest.json` 足够 AI 直接解析 |
| ★★ **接口与本地服务同源** | MCP 暴露的方法 = `GRAPH-STORAGE.md` **G6 的算法接口**（`neighborhood` / `shortest_path` / `impact` …） |
| ★★★ **不绑定任何 AI 厂商** | 标准层只给**数据与语义**；具体 MCP 实现是"参考实现"之一（可替换） |

> ★ **目的**：★ **即使 Astrolabe 这个网站没了，`.webapkg` 里的数据仍然能被任何 AI 读懂** ——
> 这才是"标准"的意义（`S2.5`：可交接性）。

## W8 版本策略

| 版本位 | 变化 | 兼容性要求 |
|---|---|---|
| **major**（`1.x.x`） | ★ 破坏性变更（删字段 / 改语义） | ⚠ 接收方**必须拒绝**不认识的大版本 |
| **minor**（`x.1.x`） | 新增**可选**字段 / 新文件类型 | ✅ 老实现**忽略即可**，不得报错 |
| **patch**（`x.x.1`） | 文档澄清 / 错误修正 | ✅ 无影响 |

★ **能力声明**：`capabilities[]` 列出本包**实际用到**的能力 ——
⚠ 接收方若缺少某项能力，应**降级处理**（忽略该部分）而不是拒绝整包。

## W9 让它真的成为标准：四个必要条件

| # | 条件 | 现状 |
|---|---|---|
| **1** ★★ | **规范自足**（不依赖私有实现就能读懂） | ★ 本文的目标 |
| **2** ★★ | **参考实现开源**（解析器 + 读图器） | `S2.1` 已定 |
| **3** ★★★ | **测试向量**（固定的样例包 + 期望解析结果） | ⚠ **待做** —— 让第三方能自测一致性 |
| **4** ★★★ | **多实现验证** | ★ **你自写的汇编解析器 = 第二个实现**（`B116`）；`AsmSymbolParser` 与 `TreeSitterParser` 产出同构，即第一层验证 |

> ★ **一句话**：**标准不是宣布出来的，是「别人照着实现成功过」之后才成立的。**
