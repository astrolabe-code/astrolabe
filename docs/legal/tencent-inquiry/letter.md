## ★ 为什么这样写（设计说明，**不要发送这部分**）

| 设计 | 理由 |
|---|---|
| ★★ **只问两个「事实性」问题** | ★ 事实性问题有确定答案 ⇒ ★ 产品团队**能直接答** ✅<br>⚠ 而「我要确认我的著作权」属于**权利性主张** ⇒ ★ 必然被转法务 ⇒ ★ 只会得到模板回复 |
| ★ **引用条款原文** | ★ 表明咨询者是认真读过协议的 ⇒ ★ 不易被当闲聊打发 |
| ★★ **顺手声明拒绝 9.4 授权** | ★ 协议 9.4 明确写了可以拒绝，★ 且给了渠道 ⇒ ★ **一次办完两件事** ✅ |
| ★★★ **不写「请确认著作权归我」** | ⚠★ 避免触发防御性答复（★ 对方一旦进入「法务口径」，★ 后续追问会越来越难）|
| ★★★ **不称「开源项目」（★ 更正过的一处）** | ⚠★ 初稿误写为「开源软件项目」—— ★ **而本项目实际未采用开源许可证**（见根目录 `LICENSE`）⇒ ★ **那是不实陈述** ⚠<br>★★ 改为「**未采用开源许可证 · 保留所有权利 · 计划将来对外授权**」：★ 既是事实 ✅，★ 又**说清了为什么要问**（要对被授权方作准确陈述）✅ |
| ★★ **交代「为什么需要确认权利状态」** | ★ 对方若不知你为何关心，★ 可能判断为「与你无关的咨询」而敷衍 ⚠<br>★★ 而「**要向被授权方作陈述**」是一个**具体、正当、可核**的用途 ✅ |
| ★ **主动提供补充信息的意愿** | ★ 降低「无法核实身份」这类程序性敷衍的概率 ✅ |
